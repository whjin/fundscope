# FundScope 网站出海实操手册

> 面向个人开发者：把 FundScope（基金持仓分析工具）从本地部署到海外可访问、可被 Google 收录、可投放 AdSense 的完整实操流程。
> 目标域名：`fundscope.wuhuajin.com`（子域名 HTTPS），主站博客 `wuhuajin.com`（GitHub Pages）。

---

## 一、出海架构总览

```
用户浏览器
    │
    ▼
  Nginx (80→443 重定向, 443 SSL 终止)   ← 阿里云 ECS
    │
    ├─ 子域名模式: fundscope.wuhuajin.com → proxy_pass 127.0.0.1:3000
    └─ 主站博客:   wuhuajin.com         → GitHub Pages (whjin.github.io)
    │
    ▼
  Node.js Express (端口 3000, PM2 守护)
    ├── /api/funds/config   基金配置
    ├── /api/fund/info      基金信息
    ├── /api/fund/holdings  持仓明细
    ├── /api/stock/quote    股票行情
    └── /*                  静态资源 + index.html
```

关键决策：**独立子域名 + 阿里云 ECS + Nginx 反代 + PM2 + Let's Encrypt**，主站博客继续留在 GitHub Pages，互不影响。

## 三、两种部署模式选择

| 对比项 | ⭐ 方案 A：子域名 HTTPS | 方案 B：子路径 HTTPS |
|---|---|---|
| 访问地址 | https://fundscope.wuhuajin.com | https://wuhuajin.com/fundscope |
| 对主站博客影响 | **无**（继续 GitHub Pages） | 需将主域 DNS 切到阿里云，主站需反代回 GitHub Pages |
| 代码改动 | 无 | 需改 server.js / app.js / index.html 适配 BASE_PATH 前缀 |
| 部署复杂度 | 简单 | 复杂 |
| 推荐度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |

**结论：优先方案 A（子域名 HTTPS）。**

## 四、方案 A：子域名 HTTPS 部署实操（推荐）

### Step 1：DNS 解析
阿里云域名控制台 → `wuhuajin.com` → 解析 → 添加 A 记录：

| 类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `fundscope` | `<服务器公网IP>` | 600 |

验证：
```bash
dig @8.8.8.8 +short fundscope.wuhuajin.com
# 期望输出: <服务器公网IP>
```

### Step 2：代码准备 + 启动服务
```bash
cd /root
[ -d fundscope ] || git clone https://github.com/whjin/fundscope.git
cd fundscope
git pull origin main
npm install --production

pm2 delete fund-server 2>/dev/null; pm2 start server.js --name fund-server
pm2 save
pm2 startup systemd   # 首次设置开机自启

curl -s http://127.0.0.1:3000/api/funds/config | head -c 100
```

### Step 3：阿里云安全组 + 防火墙
ECS 控制台 → 安全组 → 入方向开放：
- TCP 80（0.0.0.0/0）
- TCP 443（0.0.0.0/0）
- **不要开放 3000**（只允许本机访问）

```bash
firewall-cmd --permanent --add-service=http --add-service=https 2>/dev/null
firewall-cmd --reload 2>/dev/null
```

### Step 4：Nginx HTTP 配置（先用于证书签发）
```bash
mkdir -p /var/www/html && chown -R nginx:nginx /var/www/html

cat > /etc/nginx/conf.d/fundscope.conf << 'EOF'
server {
    listen 80;
    server_name fundscope.wuhuajin.com;
    location /.well-known/acme-challenge/ { root /var/www/html; try_files $uri =404; }
    location / { return 301 https://$host$request_uri; }
}
EOF

nginx -t && systemctl reload nginx
```

### Step 5：签发 SSL 证书（Let's Encrypt，webroot）
```bash
dnf install -y certbot python3-certbot-nginx 2>/dev/null || \
apt-get install -y certbot python3-certbot-nginx 2>/dev/null || true

certbot certonly --webroot -w /var/www/html -d fundscope.wuhuajin.com \
  --non-interactive --agree-tos -m your-email@example.com

ls /etc/letsencrypt/live/fundscope.wuhuajin.com/  # 应含 fullchain.pem privkey.pem
```

### Step 6：Nginx 完整 HTTPS 配置
```bash
cat > /etc/nginx/conf.d/fundscope.conf << 'EOF'
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
    listen 80;
    server_name fundscope.wuhuajin.com;
    location /.well-known/acme-challenge/ { root /var/www/html; try_files $uri =404; }
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name fundscope.wuhuajin.com;

    ssl_certificate     /etc/letsencrypt/live/fundscope.wuhuajin.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/fundscope.wuhuajin.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;
        proxy_connect_timeout 30s;
        proxy_send_timeout    60s;
        proxy_read_timeout    60s;
    }
}
EOF

nginx -t && systemctl reload nginx
```

### Step 7：验证部署
```bash
curl -I http://fundscope.wuhuajin.com/                 # 期望 301 → https
curl -I https://fundscope.wuhuajin.com/                # 期望 HTTP/2 200
curl -s https://fundscope.wuhuajin.com/api/funds/config # 期望 {"success":true,...}
certbot renew --dry-run                                # 期望 all simulated renewals succeeded
```

浏览器打开后 F12 检查：
- 地址栏小锁 ✅
- API 请求**不走 CORS 代理**（确认 `IS_STATIC=false`）✅

## 五、SEO 与广告变现合规

### 5.1 SEO 基础文件
- `sitemap.xml`：站点地图，提交 Google Search Console
- `robots.txt`：允许爬虫，指定 sitemap
- `404.html`：自定义 404（保留 404 状态码，利于 SEO 与 AdSense 校验）
- 每页 `<meta name="description">` + `canonical` 去重

### 5.2 Google AdSense 审核要点
- 提供完整合规页面：`about.html`、`contact.html`、`privacy.html`、`terms.html`、`aigc-policy.html`
- 有真实的 `ads.txt`（根目录）
- 有明确联系方式（页面 footer 邮箱）
- 有稳定、非空内容的落地页（`index.html`）
- 移动端自适应

### 5.3 合规
- 服务器在大陆时页面 footer 需展示 ICP 备案号并链接到备案查询站
- 涉及用户数据需提供隐私政策

## 七、故障排查速查

| 现象 | 排查 |
|---|---|
| 502 Bad Gateway | `pm2 list` 看 Node 是否 online → `curl 127.0.0.1:3000/api/funds/config` |
| 404 Not Found | DNS 解析是否正确 → Nginx `server_name` → 子路径注意 proxy_pass 尾部 `/` |
| 前端走 CORS 代理 | app.js `IS_STATIC` 是否误判 → 浏览器硬刷新（Ctrl+Shift+R） |
| HTTPS 证书错误 | `certbot certificates` → `certbot renew --dry-run` |
| HTTP 不跳转 | Nginx 80 端口 server 块 `return 301` → `nginx -t` |
| 子路径资源 404 | 见方案 B：BASE_PATH 前缀是否一致 |
